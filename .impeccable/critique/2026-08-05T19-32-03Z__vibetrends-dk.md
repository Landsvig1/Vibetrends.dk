## Design Specificity Verdict

**Mostly authored, with one large interchangeable hole.**

**Design review (unanchored).** The site passes the specificity test in the places that matter most. The install-command-on-card pattern on `/cli` and `/mcp` — `npx mcp-danish-weather` in a mono, paper-filled, copy-buttoned block on the *list* card — is a composition only a connectability-differentiated catalog would choose; most directories put a logo there. The hero ("Gode AI-tools. *Selv agenter* henter dem her.") is a positioning statement no other directory could reuse. The Field Notebook execution is real and held.

Four choices are category-interchangeable:

1. **`/vibes` is an unmodified Product Hunt card.** Whole card links off-site (`ProjectCard.tsx:37`, verified), no author, no tags, no connect step.
2. **The `/skills` "Emner" view is an eight-pastel-tile category grid** — the most generic layout in the SaaS vocabulary, and here it also breaks the design system.
3. **The `Dansk / Alle / Hot` filter triad renders on every hub** whether or not the data supports it.
4. **The hero's three-button CTA row** is stock startup-landing composition.

**Deterministic scan.** `detect.mjs` over `src/app` (58 files) exited 2 with **4 findings**: two `bounce-easing` (`animate-bounce` in post-submit success modals, `AgentsExplorer.tsx:399`, `VibesExplorer.tsx:403`), one `design-system-color` (`#ef4444` on the thread delete hover, `ThreadCard.tsx:71` — real palette drift, but renders only on `/forum`, off the audited surface), and one `broken-image` at `SkillDocSection.tsx:46` which is a **confirmed false positive** — the regex matched the literal string `<img>` inside a JSX comment describing the sanitizer's deny list.

**The detector's most important result is what it did not scan.** It was pointed at `src/app`, so `src/lib/` was never checked — and that is exactly where the worst palette violation lives (`skillCategories.ts:52-115`). A clean-ish detector run gave false comfort; the design review caught it. Worth remembering the next time a scan comes back quiet.

**Visual overlays: none exist.** The overlay flow (`live-server.mjs` + injected `detect.js`) only works against a localhost origin. The target was remote https, so no script was injected and there is nothing to look at in a browser. All browser findings are measured values from headless Playwright evaluation, not painted overlays.

## Overall Impression

The visual system is the strongest thing here, and it is genuinely good. The warm-paper-and-hairline restraint survives real content pressure — `/mcp` puts eight distinct elements on every card across eleven cards and still doesn't feel busy, because whitespace and a single 1px rule carry all the structure. That is hard, and most systems collapse into borders and shadows at that density. The measured accessibility floor is also better than most production sites: contrast passes everywhere with margin (worst text pair 7.81:1), every keyboard tab stop showed a visible focus ring (35/35, 45/45 across routes), every interactive element resolves an accessible name, reduced-motion genuinely suppresses the card lift rather than shortening it, and there is zero horizontal overflow at 390px.

The problem is not craft. It is that **the product's stated goal and the interface's actual behavior point in different directions.** PRODUCT.md says success is community traction and that a complete-but-inert catalog is a failure state. The interface is a well-built, inert catalog: the Forum is hidden from the nav, the primary contribute CTA is missing from the mobile menu entirely, `/vibes` sends its traffic permanently off-site, nothing anywhere shows when an entry was added, and no card links to a discussion. Every browsing surface is polished; every returning-and-contributing surface is absent or hidden.

**The single biggest opportunity:** make the contribution and community loop visible on the browsing surfaces, starting with the two self-sealing decisions — the hidden Forum and the missing mobile CTA — that cost nothing to reverse.

## What's Working

1. **Install-command-on-card (`/cli`, `/mcp`).** Putting the literal command in a mono block with a copy button on the *list* card collapses the connect path to zero navigations. It works because it makes the differentiator the visual center of the card rather than a claim in the tagline, and because monospace-means-machine is already load-bearing in the system, so the block reads as the thing itself rather than as decoration.

2. **The hairline system under density.** Structure carried entirely by whitespace and one 1px warm rule, with the near-invisible ambient shadow doing nothing more than keeping cards from looking pasted on. DESIGN.md claims this and the implementation actually delivers it.

3. **The empty state is designed, not defaulted.** `SkillsExplorer.tsx:435-450` uses the dashed 16px "unfilled slot" treatment the system specifies, names the recovery in plain Danish, and converts a dead end into the site's own conversion goal with an auth-aware handler. Treating zero results as a contribution opportunity is the right read for a traction-driven product.

## Priority Issues

### [P0] Eight saturated hues in the Skills taxonomy are a documented design-system regression

**What:** `src/lib/skillCategories.ts:52,61,70,79,88,97,106,115` hardcode `#fbbf24`, `#38bdf8`, `#60a5fa`, `#a78bfa`, `#f472b6`, `#f59e0b`, `#34d399`, `#f87171` as per-category accents, rendered as pastel icon tiles in the `/skills` → "Emner" view. Verified in source. `#a78bfa` is violet, `#38bdf8` is cyan, `#f472b6` is rose — the exact three hues DESIGN.md names as the removed prior identity, with the explicit note that "if a saturated hue reappears in this codebase, it is a regression, not a survival."

**Why it matters:** This is the loudest screen on the site and it is the one that looks like every other AI directory. It spends the argument the rest of the system is making — that this material was chosen by a person. A user who lands on Emner first sees generic SaaS, not a field notebook.

**Fix:** Delete the `accent` field from `SkillCategory` and every consumer. Differentiate the eight topics with the icon glyph, the entry count, and Forest Wash fill — the method DESIGN.md already specifies (weight, size, border, or Forest Wash, never a new hue).

**Suggested command:** `/impeccable colorize` (in its corrective sense — enforce the single-ink rule), then `/impeccable polish`

### [P0] Forum is hidden, so the product's success metric has no surface

**What:** `src/lib/hubContent.ts:84-94` `hiddenNavHrefs()` strips `/forum` and `/blog` from the header whenever their counts are zero. Verified in source and live — the desktop nav is `Vibes | Tools`. The only remaining route to Forum is a footer link.

**Why it matters:** PRODUCT.md is explicit that success is community traction and that an inert catalog is a failure state. The hiding logic is a rational anti-ghost-town heuristic, but it is self-sealing: the surface that would generate the first thread is hidden until a first thread exists. Nothing on any of the five browsed routes invites discussion, and no card links to one.

**Fix:** Replace the hide with a seeded state. Keep Forum in the nav and render the empty forum as a single authored prompt tied to real catalog content ("Ingen tråde endnu — spørg om et af de 46 skills"), pre-filling the thread from the entry the user arrived from. Add a "Diskutér" action to skill/CLI/MCP detail pages that opens a thread scoped to that entry.

**Suggested command:** `/impeccable onboard` (empty state and activation design)

### [P1] Every hub headline is English or Danglish in a declared Danish-only product

**What:** Verified live: `/skills` → "Skills Bibliotek", `/vibes` → "Project Showcase", `/cli` → "Command-line CLIs", `/mcp` → "MCP Capabilities". Page `<title>` values match ("Skills Library | vibetrends.dk"). Nav reads "Vibes" and "Tools".

**Why it matters:** Product Principle 5 is "Danish, singular — one language, written natively rather than translated," and PR #94 deliberately removed the translation layer to commit to it. The top-level surface is currently the least Danish part of the site. The stated user is a Danish builder who switched from a terminal for one concrete thing; the first words on every page are in the wrong language. This is also the highest impact-per-effort item on the list — it is copy, not architecture.

**Fix:** Rewrite the four hub H1s, their `<title>` tags, and the nav labels in native Danish. Not translated-sounding Danish: written the way the About page is written.

**Suggested command:** `/impeccable clarify`

### [P1] `/skills` is a 46-card, two-column, unpaginated wall with no count

**What:** `SkillsExplorer.tsx:410` uses `grid-cols-1 md:grid-cols-2` — half the column count DESIGN.md specifies ("typically 3 or 4 columns") — producing a 7,663px desktop and 17,350px mobile page. No result count, no pagination, no load-more, no sticky filter bar, no end-of-list marker. The filter controls scroll away after the first card and never return.

**Why it matters:** The stated operating context is a user mid-task in a terminal who arrives for one concrete thing and switches back. This layout serves browsing-for-pleasure, which is not that. It also makes 46 deliberately curated entries feel scraped, contradicting Principle 2 directly.

**Fix:** Go `lg:grid-cols-3`, cap the initial render at 12 with a `Vis flere (34)` control, put the live count beside the H1, and make the search and filter row `sticky top-16` under the header.

**Suggested command:** `/impeccable layout`

### [P1] Four hubs, four incompatible card contracts, and `/vibes` has no connect path at all

**What:** `/cli` and `/mcp` cards show install command + copy button + author + detail link. `/skills` cards show no command and route through `Forbind` → `/skills/{id}#connect`. `/vibes` cards have no author, no tags, no connect step — the whole card links off-site to `project.demoUrl` (`ProjectCard.tsx:37`, verified), with a 28x28 `Info` icon as the only route to the in-site detail page.

**Why it matters:** The one-step-to-your-agent promise is delivered on two hubs of four and contradicted on a third. A user who learns the copy affordance on `/mcp` doesn't find it on `/skills`. And `/vibes` permanently exports its traffic, which is precisely the "ends at bookmark this" failure Principle 3 names.

**Fix:** Add the install/clone block with copy to `SkillCard` — the data is already loaded (`ConnectBlock.tsx:38-39` reads `installCommand` / `githubUrl`). On `/vibes`, invert the card: primary click goes to `/vibes/{id}`, the external demo becomes a labelled secondary action, and add author + tags so a showcased project credits a person a visitor can follow.

**Suggested command:** `/impeccable shape` then `/impeccable polish`

### [P1] The primary conversion action is unreachable from the mobile menu

**What:** Verified in `Header.tsx:254-297` — the mobile panel renders the nav items, then `Log ind` (or username + `Log ud`), and ends. `Vis dit projekt`, the site's main contribute CTA, is desktop-only.

**Why it matters:** On a site whose success metric is contributions, the contribute action does not exist in mobile navigation. Combined with the hidden Forum, mobile visitors have no visible path to participate at all.

**Fix:** Add the CTA to the mobile panel as its primary action, above the auth block.

**Suggested command:** `/impeccable adapt`

## Additional Confirmed Issues

- **[P2] Keyboard and AT path breaks at catalog scale.** No skip link on any of the five routes (both assessments agree). Every hub emits `h1` → `h3` with no `h2`, so there is no heading level to navigate the grid by — measured identically at both viewports. The desktop `Tools` dropdown (`Header.tsx:93`) has `aria-haspopup="true"` but **no `aria-expanded`**, and opens via CSS `group-hover:block group-focus-within:block` rather than React state, so the state change is invisible to assistive tech. Fix: add a `Spring til indhold` skip link, wrap each hub grid in a labelled `<section>` with an `h2`, drive the dropdown from real state.
- **[P2] Sub-44px touch targets, concentrated in icon-only controls.** Measured at 390px: 28x28 on `/vibes` "Se Detaljer" (x14) and the `/cli`+`/mcp` copy-command button (x15); 32x32 source links (x15); 49x30 upvote buttons (x104 across hubs); 40x40 hamburger; 34px filter pills; 18px-tall footer links. The 28px ones are the worst because they have no adjacent text fallback.
- **[P2] Dead and misleading filter controls.** `/vibes` renders `Alle` and `Hot` with `disabled=true` and no explanation. On `/cli`, `Alle` changes the result set from 4 to 4. Three filter pills above four results signals that the chrome was built before the content. Render the filter row only when it can change the result set.
- **[P2] `ConnectBlock.tsx` breaks the Flat-By-Default Rule in six places.** Verified: `shadow-xl` at lines 40 and 90, `shadow-inner` at 48, 121, 140, `shadow-md` at 67 and 110, plus `rounded-2xl` at 40 and 90 (16px radius is reserved for empty states). The shadow vocabulary permits exactly two values, and `shadow-inner` is in neither.
- **[P2] An accent edge bar in the mobile nav — the one tell DESIGN.md names by name.** `Header.tsx:240` styles the active mobile sub-item with `border-l-2 border-accent-primary`. DESIGN.md: "An accent tab down the side of a container is the most recognizable tell of generated UI; active states here are marked with a Forest Wash fill, never with an edge bar," and separately, no border above 1px exists in the system outside the `.skill-doc` blockquote. This is the only `border-l-2` in `src/`. Neither the detector nor the design pass caught it. Replace with the Forest Wash fill already applied on the same line.
- **[P2] Two live numbers on one page that don't reconcile.** The `/skills` Emner view shows per-topic counts summing to 98; the default grid renders 46. On a site whose rule is that any number on screen must be a live DB value, this reads as one of them being wrong.
- **[P3] Card borders sit at 1.22:1 against the page.** `#e6e3dc` on `#faf9f6` measured 1.22:1, and 1.00:1 where the thumbnail placeholder badge's border matches its own backdrop. WCAG 1.4.11 wants 3:1 for boundaries conveying a control. This is in direct tension with the documented flat/no-shadow choice — with shadows off, that 1.2:1 hairline is the *only* thing separating a card from the page. Not a defect to fix blindly; a real tradeoff to decide deliberately.
- **[P3] 47 RSC prefetch requests for 11 distinct URLs on the homepage.** Each URL fetched 3-6 times with the identical `?_rsc=` token, all 200 — 67.8KB of the page's 483KB is redundant. Homepage LCP is 156ms on the hero `h1` (text, not an image) in a cold headless run, so this is not currently hurting perceived speed. Worth a look, not worth a project.
- **[P3] PRODUCT.md is stale where it declares itself authoritative.** It states the Skills taxonomy lives in `src/lib/topics.ts` with seven named categories. That file does not exist (verified); the live taxonomy is a different set of eight in `skillCategories.ts`.
- **[P3] Curation is invisible.** Nearly every `/skills` card credits the same contributor at 46 repetitions, which reads as a one-person catalog wearing community language. Nothing anywhere shows when an entry was added. Home labels a row of four as `Trending Vibe`, singular. `Se alle →` appears on some section headers and not others.

## Corrected Non-Findings

Recorded so they don't get "fixed" later:

- **Focus indicators are fine.** An automated sweep using `el.focus()` initially reported missing indicators on two `/vibes` filter buttons. That was an artifact — programmatic focus does not trigger `:focus-visible` on a `<button>`. A real keyboard Tab walk found a visible 2px forest outline at 4px offset on **every** stop across all five routes (35-45 stops each, zero misses).
- **Text contrast passes everywhere**, with the worst pair site-wide at 7.81:1 against a 4.5:1 requirement.
- **Images are not a CLS risk** despite having no `width`/`height`: all 19 are Next.js `fill` images inside fixed-height parents, so the box is reserved.
- **Fonts are correctly configured.** All 21 real `@font-face` rules use `font-display: swap`; the two rules reporting none are local metric-override fallbacks where the property does not apply.
- **`broken-image` at `SkillDocSection.tsx:46`** is a detector false positive — a string in a JSX comment, not an element.

## Persona Red Flags

**Alex (impatient power user).** Lands on `/skills` for one specific skill. No count tells him whether the catalog is worth scanning. No keyboard shortcut into search — 13 tab stops to reach the field. The placeholder promises `'Cursor', 'LangGraph'` but there is no clear-`x`, so refining means select-all-delete. **Sam (keyboard + screen reader).** No skip link on any route, so he traverses the full header before reaching `main` every time. On `/mcp` he hears "heading level 1" then eleven level-3 headings with no level 2 between — the heading structure is unusable for navigation. The `Tools` menu announces `aria-haspopup` but never `aria-expanded`, and its panel is revealed by CSS, so the state change never reaches him. On `/vibes`, the only in-site link per card is an icon button labelled solely by `aria-label` — fourteen identically-named controls in a row. Everything he *can* reach is well-marked; the problem is structure, not labels.

**Casey (distracted, one-handed, mobile).** `/skills` at 390px is 17,350px tall — about 20 screens of thumb-scroll with no pagination and no scroll-to-top. The filter row scrolls away after the first card and never returns. The hamburger panel contains Vibes, Tools, and Log ind — **the contribute CTA is not there**, so the site's main action is unreachable from mobile navigation. The `/vibes` Info button is a 28px target overlaying an image, and it is the only way to stay on the site.

**"Mikkel", the mid-task Danish builder** (project persona, PRODUCT.md's first audience). He switched from his terminal for one concrete thing and reads in Danish. Every page greets him with an English or Danglish H1 and an English browser tab. He also cannot tell a Skill from a CLI from an MCP server without opening three hubs, because no hub explains its own category and `/agent-guide` is not in the nav.

**"The coding agent"** (project persona, PRODUCT.md's second and explicitly equal audience). Not degraded on the API side — but degraded on the *human* side of the parity claim. The homepage has exactly one agent-directed link ("Er du en AI-agent? Start her →"), styled as 14px tertiary text below three buttons, and it vanishes on every hub. A human deciding whether to point their agent at this site sees no `/api/mcp` endpoint string, no example call, no "add this catalog to Claude Code" recipe — despite that being the site's whole structural thesis. The connectability of the site itself is the least visible thing on it.

## Questions to Consider

1. If the catalog is *curated, never scraped*, why does the default `/skills` view look exactly like a scrape — 46 undifferentiated cards, no editorial ordering, no "why this one is here"? Where does the curator's voice appear on any individual entry?
2. The Forum is hidden because it's empty, and it's empty partly because it's hidden. Which side of that loop are you willing to break, and what does a deliberately-designed empty forum look like?
3. `/vibes` is the only hub whose primary click permanently sends the user away. Is a showcase that generates no return visit and no connect step earning the second slot in the nav?
4. The thesis is that agents can query this catalog. A human on the homepage sees one 14px link saying so. If the agent audience is genuinely equal, what would the homepage look like if it had to convince a human to hand this URL to their agent?
5. At what catalog size does a filter start paying for the credibility it costs when it's inert?
6. Nothing on any route shows when anything was added. For a directory whose whole promise is "someone is keeping this," why is there no evidence of recent tending?
