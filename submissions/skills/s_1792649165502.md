### Beskrivelse

```text
Operational runbook for running a private, VPS-hosted autonomous revenue-signal agent (Hermes) over SSH. Documents a session discipline: verify live state before editing, probe from the VPS (not the local machine) to dodge IP-based blocks, back up files before editing, test fetchers end-to-end, and hand off state via a living roadmap file. Bound to one person's own infrastructure (custom host.env, a bespoke hermes_cli kanban board, named systemd services), so it cannot be installed or run as-is. Read as a worked example of agent-ops discipline (backup-before-edit, VPS-side probing, draft-only guardrails on spend/publish) rather than a reusable tool.
```

### Beskrivelse (dansk)

```text
Kan ikke installeres og køres af andre: hermes-ops er en privat driftsvejledning til én persons VPS-hostede agent (Hermes), bundet til vedkommendes eget host.env, et skræddersyet kanban-board og navngivne systemd-services. Værdien ligger i arbejdsdisciplinen. Skillen beskriver en fast rutine: verificer tilstanden (logs, service-status, diskplads) før ændringer, tilgå blokerede kilder fra VPS'en frem for den lokale maskine, tag backup før redigering, test hver ændring med en reel kørsel, og opdater en roadmap-fil ved sessionens afslutning. Faste regler forhindrer agenten i at sende, publicere eller bruge penge uden godkendelse, og forhindrer at API-nøgler utilsigtet skifter fakturering fra abonnement til betaling per token. Brugbar som inspiration til egen agent-drift, ikke som installerbart værktøj.
```
